# โปรแกรมซ้อมเล่น (`src/`)

วิธีใช้โปรแกรม สถานะการพัฒนา และโครงสร้างโค้ด กฎของเกมดูได้ที่ [rules-g.md](rules-g.md)

```
npm install         # ครั้งแรกครั้งเดียว
npm run dev         # เปิดโปรแกรมที่ http://localhost:3000
npm test            # เทสต์
npm run typecheck   # ตรวจ type
npm run build       # build สำหรับใช้งานจริง
```

ก่อน `dev`, `build`, `test` และ `typecheck` จะรัน `npm run content` เองทุกครั้ง เพื่อแปลงไฟล์ใน `content/` เป็น `src/data/content.json` (ดู [content.md](content.md))

## สถานะ

| ส่วน | สถานะ |
|---|---|
| เฟสและการต่อสู้ (`engine/game.ts`) | เสร็จ ครบตามกฎใน [rules-g.md](rules-g.md) ยกเว้นอัลติเมทสไตรด์ |
| ความสามารถของการ์ด (`engine/abilities.ts`) | AUTO และ ACT ทำงานอัตโนมัติจากรหัสในไฟล์การ์ด (ดูหัวข้อถัดไป) |
| หน้าสนาม (`components/`) | เล่นกับบอท (เลือกระดับใน Settings) |
| จัดเด็ค | ดู แก้ สร้าง ลบเด็คได้ เด็คที่สร้างหรือแก้เก็บในเบราว์เซอร์ |
| ภาษา (`i18n/`) | อังกฤษ (ค่าเริ่มต้น) ญี่ปุ่น |
| บอท (`bot/`) | 3 ระดับ: Normal, Hard, Nightmare (ดูหัวข้อบอท) |
| คอมโบ tutorial | มีไฟล์คอมโบและตัวโหลด (`data/combos.ts`) ยังไม่มีหน้าจอ |
| replay (`replay/`) | กดบันทึกเกมได้ ดูย้อนหลังทีละก้าว ปรับความเร็วเล่น ดาวน์โหลด/เปิดไฟล์ และเล่นต่อจากก้าวที่ดูอยู่ |
| export เด็คเป็น .yaml | ยังไม่มี |

### ระบบความสามารถ

- **ลำดับ:** เจ้าของเทิร์นทำก่อน ถ้ามีหลายอันพร้อมกันเจ้าของเลือกลำดับเอง
- **เลือกใช้:** การ์ดที่มีความสามารถรออยู่ขึ้นขอบเหลือง (การ์ดในกองหรือโซลไฮไลต์ทั้งโซน) คลิกการ์ดแล้วเป็นขอบส้ม พร้อมปุ่ม ใช่ / ไม่ ที่แถบกลาง
- **แบบเลือกได้กับแบบบังคับ:** แบบเลือกได้คือมีคอสต์ หรือผลแรกเป็นผู้เริ่มต้นคอลตัวเอง / เลือกติดฮอลโล่ว์ ถ้ากดปุ่มถัดไปโดยไม่เลือก ถือว่าไม่ใช้ ส่วนแบบบังคับไม่มีปุ่ม "ไม่" ถ้ามีอันเดียวทำงานเอง ถ้ากดปุ่มถัดไปทำเองตามลำดับเดิม
- **ข้ามเอง:** ความสามารถที่จ่ายคอสต์ไม่ได้หรือเงื่อนไขไม่ครบถูกข้ามเอง ไม่ขึ้นขอบเหลือง
- **CB / SB:** ระบบเลือกใบที่จ่ายให้เอง
- **ยังไม่รองรับ:**
  - CONT ทั้งหมด ยกเว้นเกรด +2 ของTommyตอนจ่ายคอสต์สไตรด์ (Zombie Whale −3000, ภาษีโจมตีของHonoly)
  - ACT ของSebreeze
  - อัลติเมทสไตรด์ของMegiddo
  - "ไม่เกิน 3 ใบ" ของ mill ส่งครบ 3 ใบเสมอ

### บอท

บอทเล่นฝั่ง "บอท" เสมอ รู้รายการเด็คของทั้งสองฝั่ง ไม่รู้ลำดับกองการ์ด และ (ยกเว้น Nightmare) ไม่เห็นมือของคุณ

| ระดับ | คิดยังไง | เวลาคิดต่อการตัดสินใจ |
|---|---|---|
| Normal | กฎตัดสินใจ (`bot/policy.ts`) อย่างเดียว ไม่จำการ์ดที่คุณเปิดให้เห็น | ทันที |
| Hard | กฎตัดสินใจ + จำการ์ดที่คุณเปิดให้เห็น (ไดรฟ์เช็ค ค้นขึ้นมือ) + ลองเล่นต่อในหัวทุกตัวเลือกที่สมเหตุสมผลจนจบเทิร์น (สุ่มมือที่ไม่รู้จากการ์ดที่ยังไม่ปรากฏ) เปลี่ยนจากกฎเมื่อผลดีกว่าชัดเจนเท่านั้น | ไม่เกิน 1.5 วินาที |
| Nightmare | เหมือน Hard แต่รู้มือคุณจริง จึงรู้ด้วยว่าในกองเหลือการ์ดอะไร (ไม่รู้ลำดับกอง) | ไม่เกิน 1.5 วินาที |

สิ่งที่กฎตัดสินใจคิด (ทุกระดับ):
- **นับไพ่:** ทริกเกอร์ที่เหลือในกองนับจากรายการเด็คลบการ์ดที่เปิดแล้ว (ดาเมจ ดรอป โซล ไบนด์ สนาม) คิดโอกาสเปิดแบบจั่วไม่คืนกอง
- **อ่านมือคู่แข่ง:** Shield ที่น่าจะมี จำนวนพิทักษ์ โอกาสมี Heal และ G การ์เดี้ยนที่เหลือ (การ์ดที่รู้ใช้ค่าจริง ที่ไม่รู้ใช้ค่าเฉลี่ยจากการ์ดที่ยังไม่ปรากฏ) คู่แข่งที่ยอมรับดาเมจตอนดาเมจสูงบ่อยถูกมองว่า Shield น้อยลง
- **ตี:** ตรวจ lethal ทั้งเทิร์น (คู่แข่งเลือกปล่อยลูกที่ยังไม่ถึงตาย แล้วกันที่เหลือด้วย Shield + พิทักษ์ + G การ์เดี้ยน) ถ้าฆ่าได้ตีแวนการ์ดทุกลูก ไม่งั้นเลือกตีเรียร์การ์ดที่อันตราย (อ่านสกิลและ CB/GB ของคู่แข่ง) เมื่อคุ้มกว่า ลำดับ: แวนการ์ดก่อน ยกเว้นกองเรามี Stand มากพอให้เรียร์การ์ดตีก่อน
- **การ์ด:** เลือก Shield ที่ทำให้ต้องเปิดทริกเกอร์กี่ใบจึงโดน เทียบราคาการ์ดที่เสียกับดาเมจที่คาดว่าจะโดน (นับโอกาสรอดจาก Heal ตอนดาเมจเช็ค) เก็บการ์ดไว้กันการโจมตีที่เหลือซึ่งโดนแล้วแพ้ รวมการโจมตีเพิ่มจาก Stand trigger
- **เก็บมือ:** ไม่คอลจนมือไม่พอกันแรงตีเทิร์นหน้าของคู่แข่ง (คิดว่าคู่แข่งสไตรด์)
- **คอสต์:** ลองใช้ความสามารถที่มีคอสต์ในหัวก่อน ไม่จ่ายถ้าผลไม่เกิด หรือจ่าย CB/SB แล้วไม่คุ้ม CB 2 แต้มแรกมีค่ามาก และเก็บ CB ไว้ 1 สำหรับ G การ์เดี้ยนที่ต้องจ่าย CB นอกเทิร์น
- **ดรอปโซน:** เลือก G ยูนิทตามดรอปโซน ส่งการ์ดที่คอมโบใช้ลงดรอปก่อน (ตัวที่มีผลเมื่อคอลจากดรอป, การ์ดชื่อ "Nightrose" ให้ G ยูนิทได้ Power) ไม่ส่งลงดรอปเพิ่มเมื่อกองเหลือน้อย
- **คอมโบ:** ได้ CC/SC ก่อนจ่าย CB, ติดฮอลโล่ว์ก่อนผลที่ต้องฮอลโล่ว์, Nightrose (Night Fog)เลือกคอลGrenacheกลับเพื่อ CC2 อีกรอบ (CC4 ในเทิร์นเดียว)
- **ความจำ (Hard, Nightmare):** การ์ดที่คู่แข่งเปิดให้เห็น (ไดรฟ์เช็ค ค้นขึ้นมือ) และการแสดงเกรด 3 จากมือ (คอสต์ของTommy) ใช้ตอนสุ่มมือคู่แข่งในการจำลอง

- **ไฟล์:** `view.ts` (ข้อมูลที่บอทเห็น และการสุ่มเติมข้อมูลที่ซ่อน) · `actions.ts` (การกระทำที่เป็นไปได้) · `knowledge.ts` (ค่าของการ์ด) · `eval.ts` (คะแนนสนาม) · `policy.ts` (กฎตัดสินใจ) · `search.ts` (การจำลอง) · `index.ts` (ตัวบอทและค่าของแต่ละระดับ)
- **วัดความเก่ง:** `ARENA=1 A=hard B=normal N=20 npm test -- src/bot/arena` ให้ 2 ระดับเล่นกันเอง สลับฝั่งและคนเล่นก่อน แล้วนับผล (ใส่ `MS=100` ให้คิดเร็วขึ้นได้)
- **เด็คอื่น:** กฎตัดสินใจอ่านจากรหัสความสามารถในไฟล์การ์ด ไม่ได้เขียนเฉพาะGranblue แต่ปรับค่าโดยดูเกมNightroseเป็นหลัก

## วิธีเล่นบนหน้าสนาม

เปิดโปรแกรมแล้วทั้งสองฝั่งใช้เด็คตัวอย่างใบแรก และบอทระดับ Normal เล่นฝั่งบอท ก่อนกด **Start** คลิกกองการ์ดของฝั่งไหนก็ได้เพื่อดูการ์ดทั้งเด็ค (เรียงตามเกรด 0 → 3 แบบหน้าเด็ค ไม่บอกลำดับในกอง) กด **Start** แล้วแวนการ์ดเริ่มต้นออกจากกองไปที่ VC จากนั้นจั่ว 5 ใบ

| ทำอะไร | คลิก |
|---|---|
| เปลี่ยนการ์ดบนมือ | เลือกการ์ดบนมือที่จะเปลี่ยน → **Change** (ไม่เลือกเลย = **Ready**) |
| ไรด์ | การ์ดบนมือ → VC (ไรด์แล้วไปสเต็ปถัดไปเอง) |
| สไตรด์ | ในสไตรด์สเต็ปกด "ใช่" → คลิกช่อง G โซน → G ยูนิท → การ์ดบนมือที่จะทิ้ง (เกรดรวม 3 ขึ้นไป) → "สไตรด์" |
| คอล | การ์ดบนมือ → ช่อง RC (ในเมนเฟส) |
| ย้าย | เรียร์การ์ด → ช่องหน้า/หลังในแนวเดียวกัน |
| ใช้ ACT | ยูนิทขอบเหลืองในเมนเฟส → "ใช่" |
| ใช้ความสามารถที่รออยู่ | การ์ดขอบเหลือง → "ใช่" หรือ "ไม่" |
| โจมตี | ยูนิทแถวหน้าของตัวเอง (+ ยูนิทเกรด 0-1 ข้างหลังถ้าจะบูสท์ ขอบแดงทั้งคู่) → เป้าหมายฝั่งคู่แข่ง |
| การ์ด | เลือกการ์ดบนมือ (หลายใบได้) → "ใช่" · อินเตอร์เซปต์: คลิกเกรด 2 แถวหน้า · G การ์เดี้ยน: คลิกช่อง G โซน → G การ์เดี้ยน → การ์ด Heal บนมือ → "ใช่" · จบด้วย "ไม่การ์ดเพิ่ม →" |
| ทริกเกอร์ | คลิกการ์ดทริกเกอร์บนแถบการต่อสู้ → ยูนิทรับ Power+5000 → (Critical/Stand) ยูนิทรับผลที่สอง |
| ตอบคำถามของความสามารถ | เลือกการ์ดในหน้าต่าง → "ยืนยัน" (ปุ่ม – ย่อหน้าต่างไว้ดูสนามก่อนได้) หรือเลือกยูนิท/ช่องบนสนามตามที่ถาม |
| ไปเฟสถัดไป | ปุ่มกลางสนาม เช่น "ไปเมนเฟส →", "จบเทิร์น →" |
| ย้อนกลับ / ไปหน้า | ปุ่มลูกศรด้านซ้ายของแถบกลาง (เล่นกับบอท: ย้อนไปถึงตาของคุณครั้งก่อน) |
| ดูการ์ด | คลิกการ์ดใบไหนก็ได้ รวมถึงในประวัติและในโซนต่างๆ (ชี้เมาส์ที่การ์ดบนมือก็แสดงชั่วคราว) |
| เรียงการ์ดใน G โซน | เปิดช่อง G โซน → ลากการ์ดไปวางบนใบที่ต้องการ (การ์ดชื่อเดียวกันย้ายไปด้วยกัน ลำดับถูกบันทึกลงเด็ค หน้าสร้าง/แก้ไขเด็คแสดงตามลำดับนี้) |

ปุ่มมุมขวาล่าง:
- **Reset:** เริ่มเกมใหม่ด้วยเด็คเดิม
- **Decks:** เลือก ดู แก้ หรือสร้างเด็คของแต่ละฝั่ง และสลับเด็คสองฝั่ง (⇅ Swap)
- **Replays:** เกมที่บันทึกไว้ (กด "Save this game" เพื่อบันทึกเกมที่เล่นอยู่ลงเบราว์เซอร์ เก็บ 30 เกมล่าสุด ไม่บันทึกเอง) หน้าดูย้อนหลังมีปุ่ม − / + ปรับความเร็ว 0.5x–4x กด "ดู" เพื่อเปิดหน้าดูย้อนหลัง ปุ่ม ↓ ดาวน์โหลดเป็นไฟล์ .json และเปิดไฟล์ replay จากเครื่องได้
  - **หน้าดูย้อนหลัง:** ล่างแผงขวามีตัวนับก้าว ปุ่มปิด (×) และปุ่ม ก้าวแรก / เทิร์นก่อน / ถอยหนึ่งก้าว / เล่นอัตโนมัติ / เดินหนึ่งก้าว / เทิร์นถัดไป / ก้าวสุดท้าย เห็นมือทั้งสองฝั่ง ปุ่ม "เล่นต่อจากตรงนี้" กลางแถบกลางเล่นต่อจากก้าวนั้น (บอทตามระดับใน Settings)
  - **replay ที่บันทึกก่อนกฎในโปรแกรมเปลี่ยน:** เล่นซ้ำได้ถึงก้าวสุดท้ายที่ยังใช้กับกฎปัจจุบันได้ (มีเครื่องหมาย ⚠ ที่ตัวนับก้าว)
- **Settings:** ภาษา (เปลี่ยนทันที) บอท (ปิด / Normal / Hard / Nightmare) ใครเล่นก่อน และ seed (ใส่เลขเดิม = สับไพ่เหมือนเดิม) สามอย่างหลังมีผลเมื่อกด Reset ในหน้านี้

## หลักการออกแบบ

engine เป็นฟังก์ชันล้วน รับ `state + action` คืน `state ใหม่ + events` และสุ่มด้วย seed เท่านั้น ฟีเจอร์ที่วางแผนไว้จึงใช้กลไกเดียวกันได้:

| ฟีเจอร์ | ทำงานยังไง |
|---|---|
| ย้อนกลับ / ไปหน้า | เก็บ state ก่อนหน้าไว้ทั้งก้อน (ทำแล้ว) |
| หลายภาษา | engine ไม่สร้างข้อความเอง ส่งเป็น `Msg` (key + ค่าตัวแปร) ใน `GameEvent.text`, `Decision.prompt`, `Choice.prompt` และ `RuleError.msg` หน้าจอแปลตอนแสดงผล สลับภาษาแล้วประวัติที่เล่นไปแล้วเปลี่ยนตาม (ทำแล้ว) |
| เล่นกับบอท | engine หยุดรอ `Decision` ผู้เล่นตอบผ่าน UI ส่วนบอทตอบผ่าน `Bot.decide()` (ทำแล้ว) |
| คอมโบ tutorial | ตั้งสนามตาม `setup` แล้วเทียบ action ของผู้เล่นกับ `steps` ทีละขั้น ผิดขั้นไหนบอกใบ้จาก `hint` |
| replay | เก็บ seed + เด็ค + รายการ action แล้วป้อนเข้า engine ใหม่ ไฟล์จึงเล็กและเล่นซ้ำได้ตรงทุกครั้ง (ทำแล้ว) |
| ประวัติแบบเหตุและผล | event แต่ละอันเก็บ `causeIndex` ชี้ไปที่ event ต้นเหตุ |

## โครงสร้างโค้ด

| โฟลเดอร์ใน `src/` | หน้าที่ |
|---|---|
| `app/` | หน้าเว็บของ Next.js (App Router) มีแค่ layout และ page ที่เรียก component มาแสดง |
| `components/` | ส่วนแสดงผล React รับข้อมูลและ callback ผ่าน props (`board/` คือชิ้นส่วนของหน้าสนาม, `deck/` คือหน้าจัดเด็ค) |
| `hooks/` | สถานะของหน้าจอ (`useBoard` แปลงการคลิกเป็น Action ของ engine) |
| `lib/` | ฟังก์ชันล้วนฝั่งหน้าจอ: ช่องไหนคลิกได้ ตัวเลขการต่อสู้ การแก้เด็ค การเก็บเด็คในเบราว์เซอร์ การจัดรูปแบบตัวเลข |
| `i18n/` | พจนานุกรมข้อความ (`en.ts` เป็นต้นฉบับ key, `ja.ts`) ตัวแปล `translate()` และ `useT()` สำหรับ component |
| `engine/` | สถานะเกม กฎ เฟส คิว check timing และผลของรหัสความสามารถแต่ละตัว (`types.ts` คือ type กลางทั้งหมด) |
| `effects/` | ที่ว่างสำหรับแยก handler ของรหัสผลออกมาเป็นไฟล์ละตัว ตอนนี้ยังว่าง handler ทั้งหมดอยู่ใน `engine/abilities.ts` |
| `data/` | โหลดการ์ด เด็ค คอมโบ สลีฟ จาก `content.json` และตรวจกฎจัดเด็ค |
| `bot/` | บอท 3 ระดับ (ดูหัวข้อบอท) |
| `replay/` | รูปแบบไฟล์ replay (`types.ts`), เล่นซ้ำเป็นลำดับสนาม (`play.ts`), เก็บในเบราว์เซอร์ (`store.ts`) |

## เพิ่มข้อความในโปรแกรม

- **ข้อความใหม่:** เพิ่ม key ใน `src/i18n/en.ts` ก่อน แล้วเพิ่ม key เดียวกันใน `ja.ts` (ถ้าขาดหรือเกิน `npm run typecheck` จะไม่ผ่าน) ตัวแปรเขียนเป็น `{ชื่อ}` ค่าที่เป็นตัวเลขใส่จุลภาคให้เอง ถ้าต้องผันคำตามจำนวน เช่น card/cards ในภาษาอังกฤษ ใช้ฟังก์ชันแทนข้อความได้
  - ใน engine และ lib: `msg("key", { ... })` หรือ `throw new RuleError("key", { ... })`
  - ใน component: `const t = useT()` แล้ว `t("key", { ... })` หรือ `t(msgที่ได้จาก engine)`
- **ภาษาใหม่:** สร้างไฟล์พจนานุกรมใน `src/i18n/` ตามแบบ `en.ts` แล้วเพิ่มลงใน `Locale`, `LOCALES` และ `DICTS` ของ `src/i18n/index.ts`

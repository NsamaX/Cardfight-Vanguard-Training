# ข้อมูลการ์ด เด็ค คอมโบ และรูป

ไฟล์ข้อมูลทั้งหมดเป็น YAML ใน `content/` ก่อน `dev`, `build`, `test` และ `typecheck` สคริปต์ `scripts/gen-content.mjs` จะแปลงเป็น `src/data/content.json` ให้เอง เพิ่มหรือแก้ไฟล์ระหว่างเปิด dev server ต้องรีสตาร์ต (หรือรัน `npm run content`)

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `content/cards/g/` | G ยูนิท (สไตรด์, อัลติเมทสไตรด์) และ G การ์เดี้ยน |
| `content/cards/normal/` | นอมอลยูนิท รวมเกรด 0 ที่ไม่ใช่ทริกเกอร์ |
| `content/cards/trigger/` | ทริกเกอร์ยูนิท |
| `content/decks/` | เด็คสำเร็จรูป |
| `content/combos/` | คอมโบ tutorial |
| `public/images/` | รูปการ์ด |
| `public/sleeves/` | รูปสลีฟ |

## รหัสการ์ด

**รหัสการ์ด** คือส่วนแรกของ `ids` ตัวแรกในไฟล์การ์ด เช่น `"G-CHB03/S11TH SP"` → `G-CHB03/S11TH` เด็ค คอมโบ และชื่อไฟล์รูปอ้างการ์ดด้วยรหัสนี้

การ์ดหนึ่งแบบเก็บเป็น 1 ไฟล์ ถ้าเป็นการ์ดชื่อเดียวกันที่ข้อความตรงกัน แม้พิมพ์คนละแบบ จะรวมไว้ในไฟล์เดียว

## ไฟล์การ์ด

ช่องในไฟล์: `ids`, `name`, `format`, `type`, `trigger`, `grade`, `power` หรือ `shield`, `race`, `clan`, `abilities`, `text` และ `notes` (ถ้ามี)

- **`abilities`:** รหัสสำหรับโปรแกรม แต่ละความสามารถมี `kind`, `zone`, `timing`, `cond`, `cost`, `effect` รหัสมาตรฐานดูได้ที่ [vocabulary.md](vocabulary.md)
- **`text`:** ข้อความความสามารถจริงจากการ์ด (markdown) แสดงในแผงขวาของโปรแกรม แบ่งหัวข้อตามประเภทความสามารถ เรียงดังนี้: ULTIMATE STRIDE, STRIDE, G GUARDIAN, AUTO, ACT, CONT แต่ละความสามารถแยกเป็นช่อง:

| ช่อง | ความหมาย |
|---|---|
| ช่อง | ตำแหน่งที่ความสามารถทำงาน: VC, RC, GC, มือ, G โซน |
| เงื่อนไข | GB และ 1/Turn |
| ช่วงเวลา | สเต็ปที่ใช้ได้ (สำหรับ STRIDE และ G GUARDIAN) |
| จังหวะ | เหตุการณ์ที่ทำให้ AUTO ทำงาน |
| คอสต์ | สิ่งที่ต้องจ่าย |
| ผล | ผลของความสามารถ |

รหัสจังหวะแต่ละตัวเกิดตอนไหนของเทิร์น ดูได้ที่ [timing-g.md](timing-g.md)

## ไฟล์เด็ค

ดูตัวอย่างที่ `content/decks/nightrose-sample.yaml` (เด็คเริ่มต้นของโปรแกรม)

| ช่อง | ความหมาย |
|---|---|
| `name` | ชื่อเด็ค |
| `format` | `G` |
| `starter` | รหัสการ์ดแวนการ์ดเริ่มต้น (เกรด 0 ที่นับรวมใน `main` แล้ว) |
| `main` | รหัสการ์ด → จำนวน รวม 50 ใบ |
| `g_zone` | รหัสการ์ด → จำนวน ไม่เกิน 16 ใบ |
| `sleeve`, `g_sleeve` | ชื่อไฟล์ใน `public/sleeves/` ของเมนเด็คและ G โซน (ไม่ใส่ = หลังการ์ดลายเริ่มต้น) |
| `cover` | รหัสการ์ดที่ใช้เป็นปกเด็ค (ไม่ใส่ = เลือกให้อัตโนมัติ) |

ชื่อไฟล์ (ไม่รวม .yaml) ใช้เป็น id ของเด็ค เด็คสำเร็จรูปใบแรกตามลำดับชื่อไฟล์คือเด็คที่ใช้ตอนเปิดโปรแกรม

เด็คที่สร้างหรือแก้ในโปรแกรมเก็บในเบราว์เซอร์ ไม่ได้เขียนกลับลงไฟล์ ถ้าแก้เด็คสำเร็จรูป ฉบับที่แก้จะแสดงแทนต้นฉบับ และกด Reset เพื่อคืนค่าได้

## ไฟล์คอมโบ

ดูตัวอย่างที่ `content/combos/off-turn-shot.yaml` แต่ละไฟล์มี `id`, `name`, `difficulty` (1-5), `summary`, `tags`, `setup` (สถานะสนามตอนเริ่ม), `steps` (การกระทำที่ต้องทำทีละขั้น พร้อม `hint`) และ `result`

ตอนนี้โปรแกรมโหลดไฟล์คอมโบได้แล้ว แต่ยังไม่มีหน้าจอสำหรับเล่น tutorial

## รูป

- **รูปการ์ด (`public/images/`):** PNG ขนาด 544×793 มุมมนโปร่งใส ชื่อไฟล์คือรหัสการ์ดที่เปลี่ยน `/` เป็น `_` เช่น `G-CHB03/S11TH` → `G-CHB03_S11TH.png` สร้างจากรูปต้นฉบับใน `.temp/` ด้วย `tools/clean_images.py` (ดู [tools.md](tools.md))
- **รูปสลีฟ (`public/sleeves/`):** ขนาด 440×640 สร้างจากรูปต้นฉบับใน `.temp/sleeves/` ด้วย `tools/clean_images.py` (รับ .jpg, .png หรือ .webp ที่วางเองได้ด้วย) เลือกใช้แยกเมนเด็คกับ G โซนในหน้าสร้างเด็ค หรือใส่ชื่อไฟล์ใน `sleeve` / `g_sleeve` ของไฟล์เด็ค

## เพิ่มข้อมูล

ขั้นตอนละเอียดของการเพิ่มการ์ดและสลีฟจากรูป ดู [add-card.md](add-card.md)

- **การ์ดใหม่:** เพิ่มไฟล์ .yaml ใน `content/cards/<ประเภท>/` ตามรูปแบบเดิม ถ้ามีเหตุการณ์หรือผลที่ยังไม่มีรหัส ให้เพิ่มใน [vocabulary.md](vocabulary.md) ก่อน วางรูปต้นฉบับใน `.temp/` แล้วเพิ่มบรรทัดใน `SOURCES` ของ `tools/clean_images.py`
- **เด็ค:** เพิ่มไฟล์ใน `content/decks/`
- **คอมโบ:** เพิ่มไฟล์ใน `content/combos/`
- **สลีฟ:** วางรูปต้นฉบับใน `.temp/sleeves/` แล้วเพิ่มบรรทัดใน `SLEEVES` ของ `tools/clean_images.py`

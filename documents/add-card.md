# คู่มือ AI: เพิ่มการ์ดใหม่และสลีฟจากรูป

คู่มือนี้เขียนให้ AI ทำตาม เมื่อผู้ใช้วางรูปการ์ดหรือรูปสลีฟไว้ แล้วขอให้เพิ่มเข้าคลัง ทำตามลำดับหัวข้อ และรายงานผลตามหัวข้อสุดท้าย

เอกสารที่ต้องใช้คู่กัน: [content.md](content.md) (รูปแบบไฟล์), [vocabulary.md](vocabulary.md) (รหัสความสามารถ), [timing-g.md](timing-g.md) (จังหวะ), [rules-g.md](rules-g.md) (กฎ)

## สิ่งที่ผู้ใช้เตรียมให้

| อะไร | วางที่ | ชื่อไฟล์ |
|---|---|---|
| รูปการ์ดดิบ | `.temp/` | ชื่ออะไรก็ได้ เช่น `VGE_BT02-014EN.webp` |
| รูปสลีฟดิบ | `.temp/sleeves/` | ชื่ออะไรก็ได้ |

ถ้าผู้ใช้ไม่ได้บอกชื่อไฟล์ ให้หาไฟล์ใน `.temp/` ที่ยังไม่อยู่ใน `SOURCES` (และไฟล์ใน `.temp/sleeves/` ที่ยังไม่อยู่ใน `SLEEVES`) ของ `tools/clean_images.py` ถ้าเจอหลายไฟล์ให้ถามก่อนว่าจะเพิ่มไฟล์ไหน

ห้ามแก้หรือลบไฟล์ใน `.temp/` เพราะสคริปต์ทำรูปใหม่จากไฟล์เหล่านี้ทุกครั้งที่รัน

## ส่วนที่ 1: เพิ่มการ์ด

### ขั้นที่ 1: อ่านรูปการ์ด

เปิดดูรูปแล้วจดข้อมูลต่อไปนี้ ถ้าส่วนไหนอ่านไม่ออก (ตัวเล็ก ถูกตัด เบลอ) ให้ถามผู้ใช้ ห้ามเดา

| ข้อมูล | อยู่ตรงไหนบนการ์ด |
|---|---|
| หมายเลขการ์ดและเรดริตี้ | มุมล่างซ้าย เช่น `BT02/014TH RR` |
| ชื่อการ์ด | แถบชื่อด้านล่าง |
| เกรด | มุมซ้ายบน (G ยูนิทและ G การ์เดี้ยน = 4) |
| Power / Critical | แถบล่าง |
| Shield | แถบซ้าย (การ์ดที่ไม่มีแถบ Shield เช่น เกรด 3 และ G ยูนิท ไม่ต้องใส่) |
| ไอคอนสกิล | ใต้เกรด (Boost, Intercept, Twin Drive, Triple Drive) |
| ไอคอนทริกเกอร์ และ Power บนไอคอน | มุมขวาบน (Critical, Heal, Stand, Draw) |
| เผ่า และแคลน | แถบล่างใต้ชื่อ |
| ข้อความความสามารถ | กรอบข้อความ |

**ภาษาของการ์ด:** `name`, `race`, `clan` และ `text` เป็นภาษาอังกฤษตามการ์ดฉบับ EN ส่วน `ids` ใช้หมายเลขการ์ดฉบับไทย (ลงท้ายด้วย `TH`) เพราะเด็คและรูปอ้างการ์ดด้วยหมายเลขนี้
- **รูปเป็นการ์ดภาษาอังกฤษ:** ใช้ชื่อ เผ่า แคลน และข้อความจากรูปตรงตัว แล้วถามผู้ใช้ขอหมายเลขการ์ดไทย
- **รูปเป็นภาษาอื่น:** ถามผู้ใช้ขอชื่อและข้อความภาษาอังกฤษ ถ้าผู้ใช้ให้แปลเอง ให้แปลด้วยศัพท์เดียวกับการ์ดอื่นในคลัง และเขียนใน `notes` ว่าแปลจากภาษาอะไร
- **รูปเป็นการ์ดพิมพ์ซ้ำจากภาคอื่น (เช่น D-PV01, V-SS10):** ค่าสถานะและความสามารถอาจต่างจากฉบับ G (เช่น Shield 15000 หรือทริกเกอร์ +10000) ให้ถามผู้ใช้ว่าจะใช้ค่าไหน แล้วเขียนใน `notes` ว่ารูปเป็นฉบับไหนและใช้ค่าจากที่ใด

### ขั้นที่ 2: ตรวจว่ามีการ์ดนี้อยู่แล้วหรือไม่

ค้นชื่อการ์ดใน `content/cards/` ถ้ามีการ์ดชื่อเดียวกันที่ข้อความความสามารถตรงกันทุกคำ (แค่พิมพ์คนละแบบ) ห้ามสร้างไฟล์ใหม่ ให้เพิ่มหมายเลขลงใน `ids` ของไฟล์เดิม แล้วเขียนเหตุผลใน `notes` ดูตัวอย่างที่ `Tommy the Ghostie Brothers.yaml` จากนั้นข้ามไปขั้นที่ 6

### ขั้นที่ 3: สร้างไฟล์การ์ด

**ตำแหน่ง:**

| ประเภท | โฟลเดอร์ |
|---|---|
| G ยูนิท, G การ์เดี้ยน | `content/cards/g/` |
| นอมอลยูนิท (รวมเกรด 0 ที่ไม่ใช่ทริกเกอร์) | `content/cards/normal/` |
| ทริกเกอร์ยูนิท | `content/cards/trigger/` |

**ชื่อไฟล์:** ชื่อการ์ด ตัด `,` ออก แล้วต่อด้วย `.yaml` เช่น `Undying Departed, Grenache` → `Undying Departed Grenache.yaml`

**ช่องในไฟล์ (เรียงตามนี้):**

```yaml
ids: ["BT02/014TH RR"]          # หมายเลข + เรดริตี้ตามที่พิมพ์ ส่วนแรกก่อนเว้นวรรคคือรหัสการ์ด
name: "Gust Jinn"               # ตรงตามการ์ดทุกตัวอักษร รวม ,
format: [G]
type: normal                    # normal | trigger | g-unit | g-guardian
trigger: critical               # เฉพาะทริกเกอร์: critical | heal | stand | draw
grade: 1
power: 6000                     # ตัวเลข / G ยูนิทเขียนเป็นข้อความ "15000+" / G การ์เดี้ยนไม่มี
shield: 0                       # ตามแถบ Shield บนการ์ด ไม่มีแถบ = ไม่ต้องใส่ (โปรแกรมถือว่า 0)
critical: 1
skill: boost                    # ไอคอนสกิล: boost | intercept | twin-drive | triple-drive (G การ์เดี้ยนไม่มี)
trigger_power: 5000             # เฉพาะทริกเกอร์: Power บนไอคอนทริกเกอร์
race: "Demon"
clan: "Granblue"
abilities: [...]                # ขั้นที่ 4
text: |                         # ขั้นที่ 5
  ...
notes: |                        # ไม่บังคับ
  ...
```

- ถ้าเรดริตี้ถูกตัดหรือมีตราประทับ ให้เขียนวงเล็บต่อท้ายใน `ids` เช่น `"BT02/026TH R (Fighters Road Thailand 2018 stamp)"`
- การ์ดที่ไม่มีความสามารถ ใส่ `abilities: []` และไม่ต้องมี `text`

### ขั้นที่ 4: เขียน `abilities` (รหัสสำหรับโปรแกรม)

แต่ละความสามารถบนการ์ด = 1 รายการ เรียงตามลำดับบนการ์ด ใช้รหัสจาก [vocabulary.md](vocabulary.md) เท่านั้น

```yaml
abilities:
  - kind: "AUTO"                # AUTO | ACT | CONT | STRIDE | ULTIMATE STRIDE | G GUARDIAN
    zone: "RC"                  # ช่องที่ความสามารถทำงาน: VC | RC | GC | VC/RC | hand | G zone  (ไม่ใส่ = ไม่จำกัดช่อง)
    timing: "enter(RC, self)"   # เฉพาะ AUTO, STRIDE, G GUARDIAN
    cond: ["GB(1)", "1/turn"]   # เงื่อนไข
    cost: ["CB(1)"]             # คอสต์
    effect: ["draw(1)"]         # ผล เรียงตามลำดับที่ทำ
```

- **คีย์เวิร์ด:** Hollow = AUTO `enter(RC, self)` + effect `["hollow(self)", "retire(self, at=turn-end, if=self-hollowed)"]`, Sentinel = CONT `["keyword(Sentinel)"]`, Forerunner = ดู `Undying Departed Grenache.yaml`, การ์ด Cray Elemental = CONT `["all-clan(self)"]`
- **คำในรหัสเป็นภาษาอังกฤษตามการ์ด:** ชื่อแคลนใน `filter=` และ `vc-clan(...)` ตรงกับช่อง `clan` เช่น `Granblue` คำใน `name("...")` ตรงกับคำในชื่อการ์ด เช่น `name("Nightrose")`
- **STRIDE / G GUARDIAN:** คัดลอกรูปแบบจากการ์ดประเภทเดียวกันในคลัง
- **ใช้รหัสที่ยังไม่มีไม่ได้:** ถ้าการ์ดมีเหตุการณ์ เงื่อนไข หรือผลที่ยังไม่มีรหัส ให้เพิ่มรหัสใหม่ใน vocabulary.md ก่อน แล้วบอกผู้ใช้ว่ารหัสนั้นโปรแกรมยังไม่รองรับ (ดูตารางถัดไป)

**รหัสที่โปรแกรม (`src/engine/abilities.ts`) ทำงานได้จริงตอนนี้:**

| ส่วน | รองรับ |
|---|---|
| kind | AUTO, ACT (CONT ยังไม่ทำงานเลย ยกเว้นใช้ตรวจกฎจัดเด็คเรื่องพิทักษ์) |
| timing | `enter`, `stride`, `ridden-upon`, `attack`, `battle-end`, `to-drop`, `retired`, `discarded`, `phase-start` |
| cond | `GB(n)`, `1/turn`, `own-turn`, `self-hollowed`, `vc-name(...)`, `vc-grade≥n`, `vc-clan(...)` |
| cost / effect | `CB`, `CC`, `SB`, `SC`, `mill`, `draw`, `reveal`, `discard`, `retire-own`, `retire`, `soul-in`, `bind`, `flip-G-up`, `call`, `search`, `power`, `shield`, `critical`, `no-hit`, `choose`, `hollow`, `grant`, `return-to-deck`, `swap`, `damage-facedown` |

รหัสนอกตารางนี้ยังเขียนลงไฟล์ได้ (ใช้ค้นคอมโบด้วย `tools/find_chains.py`) แต่ระหว่างเล่น ผลจะถูกข้ามพร้อมข้อความ "ยังไม่รองรับผล ... อัตโนมัติ" ในประวัติ

### ขั้นที่ 5: เขียน `text` (ข้อความที่ผู้เล่นอ่าน)

คัดข้อความภาษาอังกฤษจากการ์ดตรงตัว ไม่แก้คำ แบ่งหัวข้อตามประเภท เรียง: ULTIMATE STRIDE, STRIDE, G GUARDIAN, AUTO, ACT, CONT (ประเภทเดียวกันอยู่หัวข้อเดียว)

```markdown
### AUTO

- Hollow
- **Condition:** GB1 | **Timing:** When this unit is placed on (RC) from your drop zone | **Cost:** CB1
  - **Effect:** You may pay the cost. If you do, choose up to one of your opponent's rear-guards, and retire it.

### CONT

- Sentinel
```

- บรรทัดหลักขึ้นด้วย `- ` มีช่อง **Zone** / **Condition** / **Timing** / **Cost** เฉพาะที่การ์ดมี คั่นด้วย ` | ` (ความหมายของแต่ละช่องดู [content.md](content.md))
- **Effect** อยู่บรรทัดย่อย เยื้อง 2 ช่อง
- คีย์เวิร์ดเขียนเป็นบรรทัดเดียว เช่น `- Hollow`
- ชื่อแคลนใช้ `<<Granblue>>` ตามที่การ์ดพิมพ์
- ไอคอนบนการ์ดเขียนเป็นตัวอักษร: ช่องเขียนในวงเล็บ เช่น `(RC)` คอสต์เขียนย่อ เช่น `CB1`, `SC1`

### ขั้นที่ 6: ทำรูปการ์ด

1. เพิ่มบรรทัดใน `SOURCES` ของ `tools/clean_images.py` เรียงตามตัวอักษร: `"ชื่อไฟล์ใน .temp": "name ในไฟล์การ์ด"` (ชื่อต้องตรงกับ `name` ทุกตัวอักษร ไม่งั้นสคริปต์หยุด)
2. รัน `python tools/clean_images.py` สคริปต์จะ:
   - ตัดพื้นหลังรอบการ์ดออก
   - ปรับขนาดเป็น 544×793
   - ปรับแสงและความสดของสีให้ใกล้กับการ์ดใบอื่น
   - ทำมุมมนโปร่งใส
   - บันทึกเป็น `public/images/<รหัสการ์ด โดยเปลี่ยน / เป็น _>.png`
3. สคริปต์ทำรูปทุกใบใน `SOURCES` ใหม่ทุกครั้ง ใบที่ไม่มีไฟล์ดิบใน `.temp/` จะขึ้น "ข้าม" ซึ่งเป็นเรื่องปกติ ไฟล์ที่ทำไว้แล้วใน `public/images/` ไม่หาย
4. **เปิดดูรูปผลลัพธ์ทุกครั้ง** เทียบกับการ์ดใบอื่นใน `public/images/` ว่าตัดขอบชิดการ์ด ไม่มีขอบขาวหรือขอบดำเหลือ ไม่เอียง และสีไม่ซีดหรือจัดเกิน ถ้าผิดปกติให้แจ้งผู้ใช้พร้อมสาเหตุที่เห็น (เช่น รูปดิบมีพื้นหลังไม่ใช่สีขาว หรือถ่ายเอียง) และอย่าแก้ค่าในสคริปต์ที่ใช้กับทุกใบ

### ขั้นที่ 7: อัพเดทเอกสาร

- **[vocabulary.md](vocabulary.md):** เพิ่มชื่อการ์ดในคอลัมน์ "การ์ดที่ใช้" ของทุกรหัสที่การ์ดนี้ใช้ เพิ่มแถวในตารางหัวข้อ 5 ถ้าการ์ดนี้ก่อเหตุการณ์หรือรอเหตุการณ์ที่ต่อคอมโบกับใบอื่นได้ และแก้จำนวนไฟล์การ์ดในย่อหน้าแรก
- **[timing-g.md](timing-g.md):** เพิ่มชื่อการ์ดในคอลัมน์ "การ์ดที่ทำงาน" ของจังหวะที่การ์ดนี้ทำงาน
- ไม่ต้องใส่การ์ดลงเด็คตัวอย่าง เว้นแต่ผู้ใช้ขอ

## ส่วนที่ 2: เพิ่มสลีฟ

1. เพิ่มบรรทัดใน `SLEEVES` ของ `tools/clean_images.py`: `"ชื่อไฟล์ใน .temp/sleeves": "ชื่อสลีฟ"` ชื่อสลีฟเป็นภาษาอังกฤษตัวเล็ก ไม่มีเว้นวรรค และไม่ใส่นามสกุล เช่น `"Sleeve_Nightrose_01.png": "nightrose"` (ชื่อนี้แสดงในตัวเลือกสลีฟของหน้าสร้างเด็ค)
2. รัน `python tools/clean_images.py` สคริปต์จะตัดพื้นหลังรอบสลีฟออก ปรับขนาดเป็น 440×640 (ถ้าสัดส่วนไม่ตรง ตัดส่วนเกินจากกึ่งกลาง ไม่ยืดภาพ) แล้วบันทึกเป็น `public/sleeves/<ชื่อสลีฟ>.jpg` สลีฟไม่ปรับสีและไม่ทำมุมมน
3. เปิดดูรูปผลลัพธ์ ตรวจว่าไม่มีพื้นหลังหรือกรอบเหลือ และไม่มีส่วนสำคัญของภาพถูกตัด
4. รัน `npm run content` เพื่อให้รายชื่อสลีฟในโปรแกรมอัพเดท

## รายงานผลให้ผู้ใช้

บอกให้ครบทุกข้อ:
- ไฟล์ที่สร้างหรือแก้ พร้อม path
- ข้อมูลที่อ่านจากรูปไม่ได้ หรือที่ต้องเดา/แปลเอง (ต้องไม่มีอะไรที่เดาโดยไม่บอก)
- รหัสความสามารถที่โปรแกรมยังไม่รองรับ และผลที่จะเกิดระหว่างเล่น
- ผลการตรวจรูป และผลของ `npm run typecheck` / `npm test`
